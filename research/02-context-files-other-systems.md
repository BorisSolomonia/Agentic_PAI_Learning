# Context Files Across Agent Systems — Factual Reference

**Research date:** 2026-09-24
**Scope:** Official documentation for OpenAI Codex CLI, Cursor, Gemini CLI, GitHub Copilot (VS Code chat/Agent Host and the Copilot coding agent), Windsurf, Cline, Aider, and the AGENTS.md open format.

**Method:** every bullet is sourced to a page fetched today, cited as `(source: <URL> § <section heading>)`. A source marked `secondary` is a non-primary page (blog, community discussion) used only where no primary source existed. `UNVERIFIED` marks anything that could not be confirmed from a fetched primary source — it is never a guess.

## OpenAI Codex CLI

- **Q1 — Files & precedence**: Global scope is `~/.codex/AGENTS.md` or `~/.codex/AGENTS.override.md` (first non-empty file wins). Project scope walks from the Git root down to the current directory, checking each directory for `AGENTS.override.md` then `AGENTS.md` then any configured fallback name (one file per directory). Codex concatenates files root-down with blank-line separators; files closer to the current directory appear later in the combined prompt, so they take precedence on conflict. (source: https://learn.chatgpt.com/docs/agent-configuration/agents-md § AGENTS.md File Locations and Precedence)
- **Q2 — Imports**: Not documented. No include/import syntax between AGENTS.md files appears in the fetched docs. (source: https://learn.chatgpt.com/docs/agent-configuration/agents-md § File Inclusion/Imports)
- **Q3 — Size limit**: `project_doc_max_bytes` (config.toml) caps combined instruction size at 32 KiB by default; once reached, Codex stops adding files. `project_doc_fallback_filenames` lets a team add alternate names, checked after the standard ones. (source: https://learn.chatgpt.com/docs/config-file/config-reference § Project Documentation Discovery)
- **Q4 — System-prompt override**: `model_instructions_file` (config.toml, path) is described as a full replacement for Codex's built-in instructions; `developer_instructions` (config.toml, string) appends additional instructions. No CLI flag or environment variable for either is documented on the primary config-reference page. A GitHub discussion and an open feature request (secondary, not confirmed as shipped) discuss a `-c key=value` override pattern and ask for dedicated system-prompt flags. (source: https://learn.chatgpt.com/docs/config-file/config-reference § Instruction File Overrides; secondary: https://github.com/openai/codex/issues/11588)
- **Q5 — User vs. project config**: User-level config at `~/.codex/config.toml`; project-scoped config at `.codex/config.toml`, loaded only when the project is trusted. (source: https://learn.chatgpt.com/docs/config-file/config-reference § Config File Locations)
- **Q6 — Conditional rules**: Directory-scoped only, via where a nested `AGENTS.md` is placed (repo-wide rules at root, service-specific rules in a nested file). No glob/path-pattern targeting or model-decided relevance is documented. (source: https://learn.chatgpt.com/docs/agent-configuration/agents-md § Conditional Scoping)
- **Doc version/date**: not shown on the fetched pages (UNVERIFIED). Original URLs under `developers.openai.com/codex/...` 308-redirected to `learn.chatgpt.com/docs/...` as of 2026-09-24, indicating a recent docs migration — worth re-checking if this URL later moves again.

## Cursor

- **Q1 — Files & precedence**: Cursor auto-loads three file types: Project Rules (`.cursor/rules/*.mdc`, nested subfolders scanned), `AGENTS.md`, and `CLAUDE.md` — the last is "always applied to every conversation, regardless of any alwaysApply frontmatter setting." A separate "User Rules" tier is set in the app's Customize → Rules panel, not a repo file. Merge order on conflict: Team Rules → Project Rules → User Rules, earlier wins. (source: https://cursor.com/docs/rules § Rule locations/precedence; https://cursor.com/help/customization/rules § CLAUDE.md and AGENTS.md)
- **Q2 — Imports**: Only an `@filename.ts`-style mention inside a rule body, which pulls that file's content into context — not a dedicated import statement between two `.mdc` rule files. Whether one `.mdc` file can `@`-include another `.mdc` file specifically is UNVERIFIED. (source: https://cursor.com/docs/rules § Rule file imports/includes)
- **Q3 — Size limit**: Only a soft guideline found — "keep rules under 500 lines" — with no documented hard cutoff or truncation behavior. (source: https://cursor.com/docs/rules § Size limits)
- **Q4 — System-prompt override**: No CLI flag, environment variable, or settings key was found that replaces or appends to Cursor's base system prompt. (source: https://cursor.com/help/customization/rules — no matching section)
- **Q5 — User vs. project config**: Project Rules are version-controlled repo files; User Rules are global preferences "that apply across all projects," stored in app settings rather than a project folder. A third tier, Team Rules, appears in the precedence order but its storage location is UNVERIFIED. (source: https://cursor.com/docs/rules § User Rules)
- **Q6 — Conditional rules**: Four named rule types in current docs wording: **Always Apply** (every conversation), **Apply Intelligently** (the agent judges relevance from the rule's description), **Apply to Specific Files** (glob match, e.g. `*.tsx`), **Apply Manually** (only when explicitly @-mentioned). This supersedes older third-party terminology ("Always / Auto Attached / Agent Requested / Manual"). (source: https://cursor.com/help/customization/rules § Rule Types)
- **Doc version/date**: none shown on either fetched page.

## Gemini CLI

- **Q1 — Files & precedence**: Default filename is `GEMINI.md`, customizable via `settings.json`'s `context.fileName` (a single string or an array). Files load from three tiers — global `~/.gemini/GEMINI.md`, workspace `GEMINI.md` in the project directory and its parents, and just-in-time `GEMINI.md` files in subdirectories under the current directory (respecting `.gitignore`/`.geminiignore`) — and all discovered files are concatenated and sent with every prompt. This is additive, not an override. (source: https://github.com/google-gemini/gemini-cli/blob/main/docs/cli/gemini-md.md § Understand the context hierarchy)
- **Q2 — Imports**: `@path/to/file.md` syntax, supporting relative (`@./file.md`, `@../file.md`) and absolute (`@/absolute/path/to/file.md`) paths. Circular imports are automatically detected and prevented; maximum import depth defaults to 5 levels and is configurable. (source: https://geminicli.com/docs/reference/memport/ § Circular import detection, Maximum Import Depth)
- **Q3 — Size limit**: Not documented on either page fetched. UNVERIFIED.
- **Q4 — System-prompt override**: Environment variable `GEMINI_SYSTEM_MD` replaces the built-in system prompt entirely — `true`/`1` loads `./.gemini/system.md`, any other string is a custom path (relative, absolute, or `~`). `GEMINI_WRITE_SYSTEM_MD` dumps the current built-in system prompt to a file for review. Settings precedence, low to high: system-defaults file → user `~/.gemini/settings.json` → project `.gemini/settings.json` → system settings file → environment variables/CLI args (highest). `/memory show` and `/memory refresh` inspect and reload loaded context at runtime. (source: https://geminicli.com/docs/reference/configuration/ § Environment Variables, Settings files)
- **Q5 — User vs. project config**: User: `~/.gemini/settings.json` plus `~/.gemini/GEMINI.md`. Project: `.gemini/settings.json` plus `GEMINI.md` at the project root and subdirectories. OS-level system settings files also exist (e.g. under `/etc/gemini-cli/`, ProgramData, Library/Application Support) for admin-managed defaults or hard overrides. (source: https://geminicli.com/docs/reference/configuration/ § Settings files)
- **Q6 — Conditional rules**: None documented. `GEMINI.md` content applies unconditionally once loaded; the only "scoping" is physical directory placement (a subdirectory file loads only when the CLI operates under it) plus ignore-file exclusion — no glob-based or model-judgment conditional mechanism exists. (source: https://github.com/google-gemini/gemini-cli/blob/main/docs/cli/gemini-md.md § Understand the context hierarchy)
- **Doc version/date**: no explicit version number shown; geminicli.com is the current docs site as fetched 2026-09-24.

## GitHub Copilot (VS Code chat/Agent Host, and the Copilot coding agent)

- **Q1 — Files & precedence**: Three repo-rooted formats plus cross-tool files: (1) `.github/copilot-instructions.md` — single repo-root file, read by chat, the coding agent, and code review; (2) `.github/instructions/*.instructions.md` (optionally nested) — path-specific; (3) `AGENTS.md`, one or more files anywhere in the repo, where "the nearest AGENTS.md file in the directory tree will take precedence." VS Code's Agent Host additionally reads project `CLAUDE.md` and personal files `~/.copilot/copilot-instructions.md` / `~/.claude/CLAUDE.md`; the Copilot coding agent explicitly also honors `CLAUDE.md` and `GEMINI.md` alongside `AGENTS.md` and the `.github` formats. When a path-specific file's glob matches, its instructions apply together with the repo-wide file. (source: https://docs.github.com/en/copilot/how-tos/configure-custom-instructions-in-your-ide/add-repository-instructions-in-your-ide § Creating repository-wide custom instructions; https://github.blog/changelog/2025-08-28-copilot-coding-agent-now-supports-agents-md-custom-instructions/; https://code.visualstudio.com/docs/agent-customization/custom-instructions)
- **Q2 — Imports**: No include/import syntax found for any instruction-file type on either surface. UNVERIFIED beyond the absence of any mention.
- **Q3 — Size limit**: VS Code's docs state no size limit for instruction files. A "~1,000 lines" figure appeared only in a search-engine AI summary, not on a page fetched directly — not used as fact, UNVERIFIED. (source: https://code.visualstudio.com/docs/agent-customization/custom-instructions — no limit stated)
- **Q4 — System-prompt override**: No CLI flag, environment variable, or setting replaces the base system prompt on either surface. The closest lever, the `github.copilot.chat.codeGeneration.instructions` setting (and sibling test-generation/commit-message/PR-description settings), is deprecated as of VS Code 1.102 in favor of instruction files. (source: https://code.visualstudio.com/docs/agent-customization/custom-instructions § deprecated settings)
- **Q5 — User vs. project config**: Project: the three `.github`-rooted formats plus `AGENTS.md`/`CLAUDE.md`, all inside the repo. Personal: for VS Code's Agent Host, local files `~/.copilot/copilot-instructions.md` and `~/.claude/CLAUDE.md`, synced across machines via VS Code Settings Sync. A separate account-level "personal custom instructions" page is referenced in GitHub's docs navigation, but the expected URL 404'd on direct fetch — its current path is UNVERIFIED. (source: https://code.visualstudio.com/docs/agent-customization/custom-instructions § personal instructions)
- **Q6 — Conditional rules**: The `applyTo` frontmatter field in `*.instructions.md` takes a glob pattern "relative to the workspace root" (e.g. `applyTo: '**/*.py'`; `**` matches everything). A separate `excludeAgent` frontmatter field (added November 2025) scopes a file OUT of a given surface, e.g. `excludeAgent: "coding-agent"`. No model-judgment ("let the model decide relevance") mode analogous to Cursor's description-only rule type was found. (source: https://code.visualstudio.com/docs/agent-customization/custom-instructions § applyTo; https://github.blog/changelog/2025-11-12-copilot-code-review-and-coding-agent-now-support-agent-specific-instructions/)
- **Doc version/date**: VS Code docs cite version 1.102 for the settings deprecation; GitHub changelog entries dated 2025-08-28 and 2025-11-12.

## Windsurf

- **Q1 — Files & precedence**: As of today, `docs.windsurf.com` redirects to `docs.devin.ai/desktop/cascade/memories` — Windsurf's Cascade agent is now documented as part of Cognition's "Devin Desktop." Files: global `~/.codeium/windsurf/memories/global_rules.md`; workspace-preferred `.devin/rules/*.md`; workspace-legacy `.windsurf/rules/*.md`; legacy single-file fallback `.windsurfrules`; `AGENTS.md` is also read from any workspace directory. Enterprise deployments add OS-level system paths (macOS `/Library/Application Support/Devin/rules/*.md`, Linux/WSL `/etc/devin/rules/*.md`, Windows `C:\ProgramData\Devin\rules\*.md`). `.devin/` "is the preferred location and takes precedence, with `.windsurf/` kept as a backward-compatibility fallback"; system-level rules merge in without overriding user-defined ones. (source: https://docs.devin.ai/desktop/cascade/memories § Rule locations, reached via redirect from https://docs.windsurf.com/windsurf/cascade/memories)
- **Q2 — Imports**: No import/include mechanism is documented on the fetched page. UNVERIFIED.
- **Q3 — Size limit**: Workspace rule files are "limited to 12,000 characters per file"; the global rules file is "limited to 6,000 characters." Root `AGENTS.md` and the global file carry no frontmatter — they are always on. Behavior once a limit is exceeded is UNVERIFIED. (source: https://docs.devin.ai/desktop/cascade/memories § Character limits)
- **Q4 — System-prompt override**: No CLI flag, environment variable, or setting is documented for replacing or appending to the base system prompt. (source: https://docs.devin.ai/desktop/cascade/memories)
- **Q5 — User vs. project config**: Global rules sit once at `~/.codeium/windsurf/memories/global_rules.md`; workspace rules live inside the repo at `.devin/rules/*.md` (or the legacy paths), version-controlled per project. (source: https://docs.devin.ai/desktop/cascade/memories § Rule locations)
- **Q6 — Conditional rules**: Four named activation modes with internal values: **Always On** (`always_on`, full content every message), **Model Decision** (`model_decision`, description-only until the model judges it relevant), **Glob** (`glob`, applies when a matching file is read or edited), **Manual** (`manual`, invoked via `@rule-name`). (source: https://docs.devin.ai/desktop/cascade/memories § Activation Modes)
- **Doc version/date**: none shown.

## Cline

- **Q1 — Files & precedence**: Workspace rules live in `.clinerules/` or `.cline/rules/` (both supported, combined into one set); global rules live under an OS-specific home-directory path (`Documents/Cline/Rules` on Windows/macOS/Linux, with `~/.cline/rules` and `~/Cline/Rules` also searched). Cline additionally reads `AGENTS.md` (project root or `~/.agents/AGENTS.md`) as a cross-tool file. When both workspace and global rules exist, Cline combines them, and workspace rules take precedence on conflict. (source: https://docs.cline.bot/customization/cline-rules § rule directories and precedence)
- **Q2 — Imports**: No import/include syntax is documented for one rule file referencing another. UNVERIFIED beyond that absence.
- **Q3 — Size limit**: No hard numeric cap; only token-economy guidance — "avoid lengthy explanations or pasting entire style guides ... link to external documentation when detailed reference is needed." (source: https://docs.cline.bot/customization/cline-rules § guidance on rule length)
- **Q4 — System-prompt override**: None. Rules are described as instructions "injected into the system prompt of every conversation" — additive only, with no documented flag, environment variable, or setting that replaces Cline's base system prompt. (source: https://docs.cline.bot/customization/cline-rules)
- **Q5 — User vs. project config**: User-level rules sit once under the OS-specific home-directory path; project-level rules live inside the repo at `.clinerules/`, meant to be committed to git and shared with a team. (source: https://docs.cline.bot/customization/cline-rules § global vs. workspace rules)
- **Q6 — Conditional rules**: Workspace rule files take a YAML frontmatter `paths:` field (glob patterns using `*`, `**`, `?`, `[abc]`, `{a,b}`), so a rule activates only for matching files; each rule file also has an independent UI toggle to enable or disable it. Separately, `.clinerules/workflows/*.md` (project) or a global Workflows folder are invoked as one-off slash commands rather than applied automatically — the vendor's own docs distinguish workflows from `.clinerules`, which "append to your system prompt and affect every interaction." The current relationship between "workflows" and a newer "skills"/slash-command framing is UNVERIFIED; a workflows-specific doc page 404'd on direct fetch, so this rests partly on the vendor's own blog rather than the current docs site. (source: https://docs.cline.bot/customization/cline-rules § conditional frontmatter and toggle UI; https://docs.cline.bot/core-workflows/using-commands § slash commands; secondary: https://cline.bot/blog/stop-adding-rules-when-you-need-workflows)
- **Doc version/date**: none shown on the fetched docs.cline.bot pages; the toggle-UI and slash-command features are tied to a "Cline 3.13" product blog post (primary, exact publish date not fetched).

## Aider

- **Q1 — Files & precedence**: No auto-detected filename. `CONVENTIONS.md` is only a suggested name; any file must be loaded explicitly via `aider --read CONVENTIONS.md`, the in-chat `/read CONVENTIONS.md`, or an always-load `read:` entry in `.aider.conf.yml` (which accepts a single file or a list). (source: https://aider.chat/docs/usage/conventions.html § Always load conventions)
- **Q2 — Imports**: No syntax lets one loaded file pull in another — the config key just accepts a flat list of independent files. UNVERIFIED beyond that absence. (source: https://aider.chat/docs/usage/conventions.html § Always load conventions)
- **Q3 — Size limit**: No size limit or truncation behavior documented for `--read`/conventions files. UNVERIFIED. (source: https://aider.chat/docs/usage/conventions.html)
- **Q4 — System-prompt override**: No CLI flag or environment variable performs a full system-prompt replacement. The one documented lever is `system_prompt_prefix`, a per-model key in `.aider.model.settings.yml` that prepends text to that model's system prompt (built-in entries use it for reasoning models, e.g. `system_prompt_prefix: 'Formatting re-enabled. '` for `gpt-5-pro`/`o3`) — it prefixes rather than replaces. (source: https://aider.chat/docs/config/adv-model-settings.html § Configuration file locations)
- **Q5 — User vs. project config**: Both `.aider.conf.yml` and `.aider.model.settings.yml` are searched in the same three locations — home directory, git repo root, current directory — loaded in that order, so files loaded last (more local) take priority on conflict. `--config <file>` or `--model-settings-file <file>` pins to exactly one file, skipping the search. Every CLI flag also has a matching `AIDER_<FLAG_NAME>` environment variable. (source: https://aider.chat/docs/config/aider_conf.html § YAML config file)
- **Q6 — Conditional rules**: None documented. `--read FILE` (repeatable; env var `AIDER_READ`) only adds more always-in-context files — nothing scopes an instruction to specific files or leaves its relevance to the model's judgment. (source: https://aider.chat/docs/config/options.html — full CLI/env/YAML options reference)
- **Doc version/date**: none shown on any of the aider.chat pages fetched.

## AGENTS.md (open format)

- **Q1 — Files & precedence**: A single `AGENTS.md` per directory. The spec explicitly covers monorepos: "Place another AGENTS.md inside each package. Agents automatically read the nearest file in the directory tree, so the closest one takes precedence" — and cites the main OpenAI repo's 88 AGENTS.md files as a real-world example. The spec itself defines no global or user-level file. (source: https://agents.md/ § File Precedence & Nesting)
- **Q2 — Imports**: Not supported and not defined. The spec contains no import, include, or cross-file reference mechanism — nesting plus directory proximity is its only composition rule. (source: https://agents.md/ § Import/Include Syntax)
- **Q3 — Size limit**: None specified by the format itself. (source: https://agents.md/)
- **Q4 — System-prompt override**: Out of scope for the spec. It does not discuss a model's system prompt or how AGENTS.md content is injected relative to it — that is left entirely to each adopting tool (compare Codex CLI's `model_instructions_file` and Gemini CLI's `GEMINI_SYSTEM_MD` above). (source: https://agents.md/)
- **Q5 — User vs. project separation**: Not defined by the spec — it is inherently repo/directory-scoped (nearest-file-wins). Any user-level or global file is a tool-specific extension (e.g. Codex CLI's `~/.codex/AGENTS.md`), not part of the AGENTS.md standard. (source: https://agents.md/)
- **Q6 — Conditional rules**: None defined beyond directory proximity; no glob-based or model-decided conditional-application mechanism is part of the format. (source: https://agents.md/)
- **Doc version/date**: no version number or last-updated date shown. The site's tool-support list ("over 60 tools ... including OpenAI Codex, Google Jules, Factory, Aider, VS Code, Devin, GitHub Copilot, Cursor, JetBrains Junie, Gemini CLI") is presented as current as of today's fetch.
