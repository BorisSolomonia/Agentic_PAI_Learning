## How I like to work

- **Nothing is hardcoded.** If changing a rate, rule, date or label needs a deploy, it is a bug.
- **Verify against the source document, not the brief.** Get one real artifact before writing anything substantial.
- **Show the discrepancy, never auto-correct it.** A number that disagrees is a finding, not a defect to smooth over.
- **Surgical fixes.** Fix the actual bug with the smallest change. Never gut a component to be safe.
- **Evidence, not assertion.** Nothing is "done" until it has been looked at with a tool.
- **Terse decisions.** I answer trade-offs as numbered lines, not discussion.
- **Explain like I'm new to it.** Walkthroughs and feature docs pitched at a non-technical reader.
- **My commits are mine.** Leave changes uncommitted unless I say "push yourself".

## What frames the work

- **Correctness over speed.** A wrong number shipped fast is worse than a right one shipped late.
- **Systems over heroics.** If a result depends on someone remembering to do it, it isn't built yet.
- **Own the asset.** Bias toward equity and control over billable time.
- **Build for the ten-year profession.** The capability I'll need in a decade, not just the one that pays this month.
